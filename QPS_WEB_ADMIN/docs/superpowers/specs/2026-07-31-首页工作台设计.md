# 首页工作台设计

## 背景

当前首页只是系统欢迎页，无法承接 CRM 的日常业务。系统现有核心模块已经围绕药材基地、供应商、联系人、沟通记录、负责人和客户状态展开，首页应该从“入口页”升级为“当前销售每天打开系统后的工作台”。

本设计采用混合首页：默认展示当前登录用户负责的数据，同时提供少量整体经营视角，先满足销售跟进效率，再兼顾管理者快速了解业务结构。

## 目标

- 销售进入系统后，能立刻知道今天要联系谁、哪些客户已经逾期、哪些高意向客户需要优先处理。
- 运营或负责人能快速看到客户阶段、主营品类和最近跟进节奏。
- 首页不做复杂 BI，不引入过多筛选和配置，优先用现有 CRM 列表、联系人、沟通记录数据支撑。

## 非目标

- 第一版不做“全部/负责人切换”，数据范围默认当前登录用户。
- 第一版不做复杂地图、销售排行榜、同比环比分析。
- 第一版不新增大屏模式，不做营销型首页。

## 页面结构

### 1. 顶部 KPI

四个紧凑指标卡，展示当前登录用户范围内的数据：

- 今日待跟进：`nextFollowAt` 在今天范围内的客户数。
- 逾期未跟进：`nextFollowAt` 小于当前时间且状态不是成交/流失的客户数。
- 我的客户数：当前用户作为负责人的有效客户数。
- 高意向客户数：等级为高或 A，且未成交/未流失的客户数。

指标卡点击后进入药材基地列表，并带上对应筛选条件。

### 2. 今日待跟进列表

首页核心区域，优先展示销售下一步动作。

列表字段：

- 客户名称
- 主营品类
- 地区
- 主联系人 / 电话
- 最近沟通结果
- 下次跟进时间
- 操作：详情、记录沟通

排序规则：

1. 逾期客户排前面。
2. 今日待跟进排其后。
3. 高意向客户在同组内优先。
4. 下次跟进时间越早越靠前。

空态文案保持工作流导向：例如“今天没有待跟进客户”。

### 3. 右侧快捷区

右侧使用较窄的信息栏，避免抢列表主区域。

包含：

- 快捷操作：新增药材基地、记录沟通、查看供应商、进入数据字典。
- 最近沟通：当前用户最近 5 条沟通记录，展示客户、结果、时间和摘要。

快捷操作应使用按钮和图标，保持后台工具风格。

### 4. 图表区

图表放在首屏下半部分，用于看趋势、结构和异常，不作为页面主角。

第一版放 3 个图表：

- 跟进漏斗：待联系、跟进中、有意向、成交、流失。
- 主营品类分布：黄芪、当归、党参、天麻、其他。
- 近 7 天跟进趋势：每天沟通次数和有效沟通次数。

图表使用紧凑卡片布局，每个图表保留清晰标题、单位和空态。

## 数据范围

默认按当前登录用户过滤：

- 负责人的判断使用 CRM 客户上的 `ownerUserId`。
- 当前用户信息来自登录态中的 `userId`。
- 未分配客户不计入“我的”指标，后续可在管理视角里单独展示。

## 数据来源

第一版可以复用现有接口组合：

- 药材基地列表：`GET /api/admin/crm/herb-bases`
- 沟通记录：当前已有客户详情下的沟通记录接口；如复用成本高，可新增首页聚合接口。

推荐后端新增首页聚合接口：

- `GET /api/admin/dashboard/crm`

返回结构包含：

- `metrics`
- `todayFollowCustomers`
- `recentFollowRecords`
- `followFunnel`
- `mainProductDistribution`
- `followTrend`

聚合接口能减少首页多接口并发、重复分页和前端统计逻辑，后续也便于加权限和管理视角。

## 前端组件拆分

首页建议拆为以下组件：

- `HomeMetricCards`：顶部 KPI。
- `TodayFollowTable`：今日待跟进列表。
- `HomeQuickActions`：快捷入口。
- `RecentFollowRecords`：最近沟通。
- `FollowFunnelChart`：跟进漏斗。
- `MainProductDistributionChart`：主营品类分布。
- `FollowTrendChart`：近 7 天跟进趋势。

页面文件负责取数、loading、错误态和组件布局；展示组件只接收 props。

## 布局和视觉原则

- 后台系统优先信息密度和可扫描性，避免营销型大 hero。
- 采用全宽工作台布局，不把整个页面包成大卡片。
- KPI 卡片保持 8px 内圆角，图表和列表使用克制边框。
- 页面主色跟随现有 Element Plus 主题，不引入大面积渐变背景。
- 表格操作列保持统一按钮间距，避免拥挤和换行。

## 异常和空态

- 首页接口失败：显示轻量错误提示，并保留页面结构，可点击重试。
- 指标为空：显示 0，不显示短横线。
- 列表为空：显示明确空态，不误导为加载中。
- 图表无数据：显示空态占位，并保留标题和图表区域高度，避免布局跳动。

## 测试策略

后端：

- 聚合接口按当前用户过滤数据。
- 今日待跟进、逾期、高意向、漏斗和趋势统计的边界日期测试。
- 无数据时返回空数组和 0 指标。

前端：

- Playwright 覆盖首页加载、KPI 可见、待跟进列表、图表空态/有数据态。
- mock 当前用户数据，避免写真实数据库。
- 构建验证使用 `npm.cmd run build`。

## 验收标准

- 登录后首页不再只是欢迎页，而是可操作的 CRM 工作台。
- 当前用户能看到今日待办、逾期待办、我的客户和高意向客户。
- 今日待跟进列表能直接进入详情或记录沟通。
- 页面包含跟进漏斗、主营品类分布、近 7 天跟进趋势。
- 首页无数据、接口失败、加载中都有明确状态。
- 不清理或重置 CRM 业务数据。
