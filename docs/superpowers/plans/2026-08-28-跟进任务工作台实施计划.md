# 跟进任务工作台实施计划

> **供自动化执行者使用：** 必须使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，逐任务执行并在任务间复核。每个步骤均使用复选框跟踪。

**目标：** 新增一个仅展示当前负责人的基地主体、厂商待跟进事项的统一工作台，并复用既有沟通记录完成闭环。

**架构：** 不创建任务表。工作台从主体、厂商的跟进摘要字段派生状态，应用层将两类对象投影为统一 DTO 并合并分页。厂商通过与主体一致的 `UpdateFollowSummary` 维护摘要，`CrmFollowRecord` 始终是沟通明细来源。

**技术栈：** .NET 8、EF Core、SQL Server、MediatR、Vue 3、TypeScript、Element Plus、Vitest/浏览器验收。

**设计依据：** [跟进任务工作台设计方案](../specs/2026-08-28-跟进任务工作台设计方案.md)

## 全局约束

- 不创建 `CrmTask`、任务完成状态、任务分配或消息提醒。
- 基地主体和厂商均只排除已删除数据；主体成交、流失状态不参与过滤。
- 工作台只按 `OwnerUserId == 当前登录用户` 查询，不增加团队或全部数据范围。
- 不修改 `TestDataInitializer`，结构、索引、权限和历史回填都由 EF Migration 处理。
- 现有项目没有迁移历史，必须先建立空基线迁移，再建立本功能增量迁移。
- 临时测试脚本、接口验收脚本、截图和构建产物只能存放在 `C:\Users\Dust\AppData\Local\Temp\QPS`，不得新增到仓库测试目录。
- 不引入第三方依赖，不改动基地与主体已分离的维护入口。

- 产出：`CrmFollowTaskResponse`，包含 `Overview`、`List`、`Total`、`Page`、`PageSize`。

- [ ] **步骤 1：定义请求、枚举值和返回 DTO**

请求字段限定为 `Category`（空、`OVERDUE`、`TODAY`、`FUTURE`、`NO_PLAN`）、`EntityType`（空、`CRM_HERB_BASE_SUBJECT`、`CRM_VENDOR`）、`Keyword`、`Page`、`PageSize`。返回 DTO 包含：

```csharp
public Guid EntityId { get; init; }
public string EntityType { get; init; } = string.Empty;
public string EntityName { get; init; } = string.Empty;
public string ContactName { get; init; } = string.Empty;
public string ContactPhone { get; init; } = string.Empty;
public DateTime? LastFollowAt { get; init; }
public string LastFollowResult { get; init; } = string.Empty;
public DateTime? NextFollowAt { get; init; }
public string Category { get; init; } = string.Empty;
```

概览 DTO 固定包含 `OverdueCount`、`TodayCount`、`NoPlanCount`、`CompletedLast7DaysCount`；响应 DTO 固定包含 `CrmFollowTaskOverviewDto Overview`、`List<CrmFollowTaskDto> List`、`int Total`、`int Page`、`int PageSize`。

- [ ] **步骤 2：实现按当前负责人过滤的双对象投影**

解析 `ICurrentUserService.UserId`；无法解析时返回空分页和全零概览。分别从主体、厂商查询 `!IsDeleted && OwnerUserId == currentUserId`，再投影为相同匿名形状。

主体联系人使用已有 `PrimaryContactName`、`PrimaryContactPhone`；厂商联系人使用 `CrmContacts` 中未删除、非 `INVALID`、主联系人优先且创建时间最早的一条。厂商、主体的 `LastFollow*` 和 `NextFollowAt` 直接取摘要字段。

- [ ] **步骤 3：实现统一分类、过滤、排序和统计**

使用同一个 `now`、`todayStart`、`tomorrowStart` 计算分类。筛选应用在合并后的统一查询上；关键字同时匹配对象名称、联系人、联系电话。固定排序表达式为：

```csharp
.OrderBy(task => task.CategoryOrder)
.ThenBy(task => task.NextFollowAt == null ? task.LastFollowAt : task.NextFollowAt)
.ThenBy(task => task.EntityName)
```

概览前三项按同一对象范围分别计数；近 7 天已完成对 `CrmFollowRecords` 按当前用户负责对象和实体类型计数，范围为当天零点向前 6 天至次日零点之前，且不按沟通结果过滤。

- [ ] **步骤 4：暴露控制器并执行接口验收**

控制器只绑定查询参数并通过 MediatR 发送。临时 PowerShell 脚本依次请求全部、四类分类、主体筛选、厂商筛选和关键字筛选，检查：

```powershell
$result.data.list | ForEach-Object { $_.ownerUserId -eq $currentUserId }
$result.data.list | ForEach-Object { $_.entityType -in 'CRM_HERB_BASE_SUBJECT','CRM_VENDOR' }
```

另构造一个其他负责人对象，确认接口不返回该对象；构造已成交主体，确认仍返回。
