# 中药材品类统一字典实施计划

> **面向执行代理：** 必须使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 按任务执行，并用复选框跟踪。

**目标：** 基地与厂商采购计划统一使用“中药材品类”数据字典中的启用品类。

**架构：** 复用 `SystemDataDictionaries` 作为唯一品类主数据，继续以 `CrmBusinessEntityAttributes` 保存两类多选属性。应用层集中校验，前端调用统一只读选项接口，迁移从已有属性值反向补齐字典。

**技术栈：** .NET 8、EF Core 8、SQL Server、MediatR、Vue 3、TypeScript、Element Plus。

**设计依据：** [中药材品类统一字典设计方案](../specs/2026-08-31-中药材品类统一字典设计方案.md)

## 全局约束

- 不新增品类业务表；子项 `Code`、`Name`、`Value` 均为相同的中文品类名。
- 基地主营品类为 `CRM_HERB_BASE / CRM_MAIN_PRODUCT`；采购品类为 `CRM_VENDOR_PURCHASE_PLAN / PURCHASE_PRODUCT`。
- 停用品类仍展示和统计，但不能新选、编辑或筛选；根节点与子项均不能删除。
- 临时脚本、测试、截图仅放在 `C:\Users\Dust\AppData\Local\Temp\QPS`。
- 不回滚或提交用户已有未提交改动。

- [ ] **步骤 1：编写迁移前置检查**

SELECT DISTINCT LTRIM(RTRIM(AttributeValue)) AS ProductName
FROM CrmBusinessEntityAttributes
WHERE IsDeleted = 0

- [ ] **步骤 3：实现统一查询和校验**
`GetActiveNamesAsync` 查询未删除根节点下未删除、启用的子项，按名称返回 `HashSet<string>(StringComparer.Ordinal)`；根节点不存在时抛出“中药材品类字典未初始化”。
`ValidateActiveNamesAsync` 标准化空白、去重后分别对全部子项和启用子项校验：不存在抛出“品类未在中药材品类字典中维护”，已停用抛出“品类已停用，请重新选择”。
