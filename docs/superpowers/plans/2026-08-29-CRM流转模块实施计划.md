# CRM 流转模块实施计划

> **供执行代理使用：** 使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 按任务逐项执行；使用复选框追踪。

**目标：** 让主体和厂商的每次负责人变更都有流转历史，并从厂商编辑中彻底移除负责人修改。

**架构：** 主体、厂商各自保存当前负责人；聚合根 `ChangeOwner(...)` 创建并返回流转记录，应用层完成权限、加载、追加和一次保存。创建入口直接生成 `ENTRY`，不把入库伪装为负责人变更。

**技术栈：** .NET 8、EF Core 8、SQL Server、MediatR、Vue 3、TypeScript、Element Plus。

**设计：** [`docs/superpowers/specs/2026-08-29-CRM流转模块设计.md`](../specs/2026-08-29-CRM流转模块设计.md)

## 全局约束

- 只有基地主体、厂商参与流转；基地明细不参与。
- 页面使用中文“流转”；动作代码固定 `ENTRY`、`ASSIGN`、`TRANSFER`、`RETURN`。
- 不新增当前状态表、`Service`、领域事件或接收确认流程。
- `OwnerUserId` 只允许在创建初始状态和统一流转命令中变化；厂商编辑请求不得包含该字段。
- `CRM_TRANSFER` 管理人员可分配、转交、退回、批量操作；当前负责人只能退回本人对象。
- 所有新增测试、构建输出、截图和回填记录放在 `qps-ui-tests/CRM流转测试/`，不得提交仓库。

- [ ] **步骤 1：生成并补充迁移。** `ActionType` 先可空后非空（默认 `ENTRY`，长度 16）。按 `EntityType + EntityId` 的 `CreatedAt, Id` 顺序将最早记录回填 `ENTRY`，后续按前后负责人回填三种变更动作；为无记录的主体、厂商补“历史数据初始化”入库记录。回填不得更新 `OwnerUserId` 或删除记录。
- [ ] **步骤 2：写幂等权限 SQL。** 沿用 `AddCrmFollowPermission`，创建“流转管理”权限码 `CRM_TRANSFER`，挂在 `ROOT` 下并授予 `admin`。
- [ ] **步骤 3：在备份库验证。**

```sql
SELECT ActionType, COUNT(*) FROM CrmTransferRecords WHERE IsDeleted = 0 GROUP BY ActionType;
SELECT 'CRM_HERB_BASE_SUBJECT', Id FROM CrmHerbBaseSubjects s WHERE NOT EXISTS
 (SELECT 1 FROM CrmTransferRecords r WHERE r.EntityType='CRM_HERB_BASE_SUBJECT' AND r.EntityId=s.Id)
UNION ALL
SELECT 'CRM_VENDOR', Id FROM CrmVendors v WHERE NOT EXISTS
 (SELECT 1 FROM CrmTransferRecords r WHERE r.EntityType='CRM_VENDOR' AND r.EntityId=v.Id);
```

预期：第二个查询为零行，迁移前后 `Id + OwnerUserId` 完全一致。
