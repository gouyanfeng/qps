# 基地供应信息标准化 Implementation Plan

> **历史实施记录：** 基地供应信息已实施并验证。本文保留原始实施步骤，不作为当前执行清单。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为具体药材基地建立带主体冗余、状态和有效期的结构化供应信息，并在基地详情中维护。

**Architecture:** 新增 `CrmHerbBaseSupply` 领域实体，`HerbBaseId` 是唯一业务归属，`HerbBaseSubjectId` 是从基地同步的查询冗余字段。应用层负责供应信息的 CRUD、状态校验和主体详情聚合；数据库迁移从现有主营品类幂等生成待确认记录；前端在既有基地详情抽屉中按基地呈现和维护。

**Tech Stack:** .NET 8、EF Core、MediatR、SQL Server、Vue 3、TypeScript、Element Plus。

**Spec:** `docs/superpowers/specs/2026-09-02-基地供应信息标准化设计方案.md`

## Global Constraints

- 供应信息必须归属具体基地；`HerbBaseSubjectId` 是可空冗余字段，始终同步 `CrmHerbBase.HerbBaseSubjectId`，不可由请求独立设置。
- 只允许状态为“有效”且 `ValidUntil >= DateTime.Today` 的记录作为未来匹配候选；本期不实现匹配、库存扣减、订单占用或自动到期任务。
- 转“有效”时必须有品类、正数可供量、数量单位、核实日期和不早于核实日期的有效截止日；已失效不可恢复，只有待确认可删除。
- 历史主营品类仅生成“待确认”供应信息；迁移必须幂等，且不覆盖主营品类属性。
- 所有新测试、接口脚本和浏览器验收产物放入 `codex-temp`，不新增仓库测试文件。
