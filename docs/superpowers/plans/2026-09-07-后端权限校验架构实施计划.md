# 后端权限校验架构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 以 `PermissionAttribute` 和 MediatR `PermissionBehaviour` 统一撮合机会模块的功能权限校验，并保留 Handler/领域层的业务状态规则。

**架构：** Query、Command 用单个 `PermissionAttribute` 声明静态权限码；`PermissionBehaviour` 在 Handler 前读取并缓存请求类型元数据，实时查询当前用户、单角色及角色权限。撮合模块删除手工权限助手；候选查询不标记权限特性，业务状态、数据范围和关联引用校验不迁移出 Handler/领域规则。

**技术栈：** .NET 8、MediatR 14、EF Core 8、xUnit、EF Core InMemory。

**设计依据：** `docs/superpowers/specs/2026-09-07-后端权限校验架构设计方案.md`

## 全局约束

- 权限特性命名为 `PermissionAttribute`，权限码常量定义在 `QPS.Application.Features.System.SystemPermissionCodes`。
- 权限常量名与权限码字符串完全一致，例如 `CRM_MATCH_OPPORTUNITY_VIEW = "CRM_MATCH_OPPORTUNITY_VIEW"`。
- MediatR 顺序固定为 `PermissionBehaviour -> ValidationBehaviour -> TransactionBehaviour -> Handler`。
- `PermissionBehaviour` 只校验用户有效性和功能权限，不处理业务状态、数据范围、资源归属或关联引用。
- 临时测试项目和测试源放在 `E:\Code\QPS\codex-temp`，不写入业务测试目录。
- 不修改前端代码、Controller 路由、JWT 认证中间件和撮合生命周期规则。
