# 人工供需撮合机会闭环扩展实施计划

> **给执行代理的要求：** 使用 `superpowers:executing-plans` 按任务执行；每完成一项立即更新复选框。

**目标：** 为现有人工撮合机会补齐中选、关闭结果、候选实时状态和采购需求保护，形成可回查的最小业务闭环。

**架构：** `CrmMatchOpportunity` 与 `CrmMatchCandidate` 继续保存不可变快照和状态；Application 层负责跨聚合查询、当前供应有效性校验及活动记录编排。候选当前状态是详情查询派生值，不新增冗余列；前端沿用现有 `QueryPage`、业务页面和详情抽屉，不改公共组件。

**技术栈：** .NET 8、EF Core 8、SQL Server、MediatR、Vue 3、TypeScript、Element Plus、Playwright。

**设计依据：** `docs/superpowers/specs/2026-09-05-人工供需撮合机会设计方案.md`

## 全局约束

- 权限现状不在本轮修改范围内。
- 状态、关闭结果和候选状态接口值统一使用中文。
- 当前供应有效性按服务端北京时间判断：状态为“有效”且有效期不早于当天。
- `CloseResult` 仅在机会关闭时有值；成功必须至少一条当前有效的中选候选，非成功必须填写关闭原因且不能保留中选候选。
- 不做价格、数量、单位换算或候选承担数量、订单、库存和履约。
- 临时后端测试放在 `E:\Code\QPS\codex-temp`；浏览器验收资产放在 `E:\Code\QPS\ui-tests`，不得提交。
