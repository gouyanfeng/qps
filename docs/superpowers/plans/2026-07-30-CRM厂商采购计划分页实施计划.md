# CRM厂商采购计划分页 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 厂商详情抽屉中的采购计划改为分页加载，并给优先级标签补充规则提示。

**架构：** 后端新增厂商采购计划分页查询和控制器子路由，详情接口不再一次性返回最近 100 条采购计划。前端详情抽屉维护独立的采购计划分页状态，打开详情和翻页时分别加载对应页数据。

**技术栈：** .NET 8、EF Core、MediatR、SQL Server、Vue 3、Element Plus、QueryPage。

## 全局约束

- 所有沟通和交付说明使用中文。
- 页面只读，不新增、编辑、删除厂商数据。
- 采购计划来自 `CrmVendorPurchasePlans`。
- 前端和后端测试产物放到 `E:\Code\QPS\codex-temp`。
- 本地接口继续使用 `http://localhost:20004/api`，不换端口。

### 任务 1: 后端采购计划分页接口

**文件：**
- 新增： `QPS-HT/src/2.QPS.Application/Features/Crm/CrmVendors/GetCrmVendorPurchasePlansQuery.cs`
- 修改： `QPS-HT/src/2.QPS.Application/Features/Crm/CrmVendors/GetCrmVendorQuery.cs`
- 修改： `QPS-HT/src/4.QPS.WebAPI/Controllers/Admin/Crm/CrmVendorController.cs`

**接口：**
- 输入：
  - `CrmVendorPurchasePlans`
  - `CrmVendorPurchasePlanDto`
- 输出：
  - `GetCrmVendorPurchasePlansQuery : PaginationRequest, IRequest<PaginationResponse<CrmVendorPurchasePlanDto>>`
  - `GET /api/admin/crm/vendors/{id}/purchase-plans`

- [ ] **步骤 1: 新增分页查询**

新增 `GetCrmVendorPurchasePlansQuery`，参数包含 `VendorId`、`Page`、`PageSize`、`SortField`、`SortDirection`。

- [ ] **步骤 2: 查询前校验厂商存在**

查询 `CrmVendors`，若厂商不存在或已删除，抛出 `BusinessException(404, "厂商不存在")`。

- [ ] **步骤 3: 返回分页采购计划**

从 `CrmVendorPurchasePlans` 查询当前厂商未删除计划，默认按 `PurchaseTime` 倒序，再按 `CreatedAt` 倒序，映射为 `CrmVendorPurchasePlanDto` 并返回分页响应。

- [ ] **步骤 4: 详情接口去掉固定 100 条采购计划**

`GetCrmVendorQuery` 不再加载 `PurchasePlans`，仅保留 `PurchasePlanCount`。

- [ ] **步骤 5: 控制器新增子路由**

在 `CrmVendorController` 增加 `GET {id}/purchase-plans`，接收 `page`、`pageSize`、`sortField`、`sortDirection`。

详情抽屉中的采购计划表格改用 `purchasePlans`，表格 loading 使用 `purchasePlanLoading`。

表格下方增加 `el-pagination`，支持页码切换和每页条数切换，默认每页 10。
