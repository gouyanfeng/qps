# 人工供需撮合机会实施计划

> **给执行代理的要求：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行。任务步骤使用复选框跟踪进度。

**目标：** 建设以采购需求明细为入口的人工候选筛选与撮合机会工作台，记录候选判断和撮合推进过程。

**架构：** 新增撮合机会、候选和最小通用过程记录三个领域实体；采购需求和供应信息继续是来源事实，机会和候选保留本轮判断快照。应用层提供候选筛选、创建、推进和详情时间线；前端沿用 `QueryPage + el-table + 详情抽屉`。

**技术栈：** .NET 8、EF Core 8、MediatR、SQL Server、Vue 3、TypeScript、Element Plus、Playwright。

**设计依据：** `docs/superpowers/specs/2026-09-05-人工供需撮合机会设计方案.md`

## 全局约束

- P0 仅支持人工筛选、候选判断与机会推进；不建设自动推荐、报价、样品、验收、合同、订单、成交、库存扣减或复购。
- 候选供应必须同品类、状态为“有效”且 `ValidUntil >= DateTime.Today`。
- 状态和动作使用中文：机会为“推进中、暂停、已关闭”，候选为“待评估、保留、淘汰”。
- `CrmBusinessActivities` 仅保存 `EntityType`、`EntityId`、`ActionType`、`Content` 和审计字段；`CreatedBy` 保存操作用户 ID，查询时关联 `SystemUsers` 展示姓名。
- 后端临时验证放在 `E:\Code\QPS\agent-temp`，不提交；真实 UI 用例放在 `E:\Code\QPS\ui-tests`，隔离端口固定为 `5174/5001`。
- 不修改 `QueryPage`；菜单维护在 `admin/src/assets/json/authMenuList.json`。
