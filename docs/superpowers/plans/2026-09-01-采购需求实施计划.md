# 采购需求实施计划

> **执行要求：** 按任务逐项实施并勾选；每项完成后进行代码审查和验证，再进入下一项。

**目标：** 将厂商采购计划完整迁移为可维护、可筛选、可流转状态的采购需求，并用逐品类明细承载数量、规格、质量、价格和交期。

**架构：** `CrmPurchaseDemand` 是需求聚合根，`CrmPurchaseDemandItem` 是其内部明细；需求不存独立跟进人，查询时关联厂商当前跟进人。应用层以 MediatR 命令和查询编排校验与持久化，领域实体负责自身字段和状态约束；前端沿用 `QueryPage + el-table` 与既有厂商详情抽屉模式，不修改通用组件。

**技术栈：** .NET 8、EF Core 8、MediatR、SQL Server、Vue 3、TypeScript、Element Plus、ECharts。

**设计依据：** [采购需求标准化设计方案](../specs/2026-09-01-采购需求标准化设计方案.md)

## 全局约束

- 数据库、实体、接口、前端路由和页面文案统一使用“采购需求”，不保留采购计划兼容入口。
- 历史采购计划全部迁移为“待确认”采购需求，不自动转为有效。
- 跟进人只取 `CrmVendor.OwnerUserId`，不在需求表或流转模块新增跟进人字段。
- 品类只能使用启用的 `CRM_HERB_PRODUCT` 字典值；数量单位首批仅“吨、公斤、克、件、批”。
- 状态保存中文值：`待确认`、`有效`、`匹配中`、`已完成`、`已关闭`；来源类型保存中文值：`外部来源`、`人工录入`。
- 临时脚本、测试文件、构建产物和截图统一存于 `C:\Users\Dust\AppData\Local\Temp\QPS`，不加入仓库。
- 不修改 `QueryPage`、通用表格或全局菜单组件；新页面沿用现有模式。
