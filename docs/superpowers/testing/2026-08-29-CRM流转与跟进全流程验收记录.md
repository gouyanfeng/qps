## 管理员首轮详细验收方案

### 测试数据分组

| 分组 | 对象 | 数量 | 用途 |
| --- | --- | --- | --- |
| A | 基地主体与基地 | 1 条 | 联系人、沟通、状态、单条流转、详情回查 |

### 阶段 0：环境与权限

1. 使用 `admin` 登录，确认基地管理、厂商管理、跟进任务和系统设置可访问。
2. 确认管理员可见流转管理入口，待分配对象显示“分配”，已分配对象显示“转交、退回”。
3. 只读检查后端健康接口、新 `PATCH /owner` 路由和旧 `/assign-owner` 路由状态。
4. 保存管理员页面与权限入口截图。

### 阶段 1：基地主体完整功能

1. 新增 A 组基地，填写名称、品类、规模、地区、地址、来源和备注。
2. 搜索并打开详情，确认基地数、规模、地区、地址、品类；确认跟进人为系统管理员，流转记录为“入库：未分配 至 系统管理员”。
3. 新增联系人，编辑电话、微信、角色和备注，并设为主联系人；列表和详情应同步显示主联系人。
4. 新增电话沟通记录，填写沟通结果、意向等级、下次跟进时间和备注；确认详情时间线、最近沟通、下次跟进更新。
5. 进入跟进任务工作台，确认 A 组主体以待跟进事项出现，点击详情能正确打开基地详情。
6. 依次标记有意向、成交；确认列表和详情状态一致。流失仅在另一条独立测试对象上验证，避免与成交状态相互覆盖。
7. 对 A 组主体执行：退回待分配池 -> 分配给系统管理员 -> 转交给普通用户 -> 管理员退回待分配池 -> 重新分配给系统管理员。
8. 每一步确认动作类型、原跟进人、目标跟进人、操作人、备注和刷新后的持久化结果。

### 阶段 2：基地批量流转

1. 新增 B 组两条基地，确认两条均自动入库至系统管理员。
2. 在列表勾选两条，批量退回；确认两条均变为待分配且各自新增 `RETURN` 记录。
3. 勾选两条，批量分配给普通用户；确认两条均新增 `ASSIGN` 记录。
4. 勾选两条，批量转交回系统管理员；确认两条均新增 `TRANSFER` 记录。
5. 分别打开两条详情，排除只更新列表或仅更新第一条的风险。

### 阶段 3：厂商完整功能

1. 新增 C 组厂商，并在请求中保留非当前操作人的 `OwnerUserId` 场景；确认实际跟进人仍是系统管理员，首条记录为 `ENTRY`。
2. 编辑厂商资料，确认编辑页没有跟进人可修改入口，且资料更新后跟进人不变。
3. 新增并编辑联系人，设为主联系人；确认厂商列表和详情同步显示。
4. 新增采购计划并选择计划品类；确认品类数量和详情列表更新。
5. 编辑采购计划品类；确认计划数量、最近采购信息和采购概况更新。
6. 新增电话沟通记录，设置下次跟进；确认详情时间线、最近沟通、下次跟进与跟进任务工作台一致。
7. 对 C 组厂商执行与 A 组相同的单条流转链路，并核对四种动作。

### 阶段 4：厂商批量流转

1. 新增 D 组两条厂商，确认自动入库。
2. 批量退回、批量分配给普通用户、批量转交给系统管理员。
3. 对两条厂商分别进行详情和刷新回查，确认流转记录均完整。

### 阶段 5：统一回查与边界

1. 分别刷新基地、厂商和跟进任务页面，重新搜索全部 A、B、C、D 测试对象。
2. 只读接口回查每个对象的跟进人、沟通记录和流转记录动作顺序，和页面逐项核对。
3. 检查同一测试对象的详情点击只发起一次详情请求，且基地、厂商详情不会串对象。
4. 在操作日志中按测试名称查询，确认创建、编辑、沟通、流转等管理员操作可追溯。
5. 保存最终截图和测试结果；本轮结束后再切普通用户执行权限边界 P02、P03。

### 阶段 6：资料维护、校验与列表行为补充

本阶段是管理员首轮的必要组成部分，不以主流程通过替代以下功能验收。

#### 基地主体与基地维护

1. 对 A 组主体执行编辑，修改主体备注；确认主体名称、跟进人、评分和等级不出现人工修改入口，保存后原流转记录不变化。
2. 在 A 组主体新增第二个基地，编辑其规模、地区、地址、来源和主营品类；确认主体汇总的基地数、总规模和品类同步更新。
3. 删除该第二个基地；确认仅删除测试新增基地，主体汇总恢复，原始基地、联系人、沟通记录和流转记录仍存在。
4. 联系人执行新增、编辑、设为主联系人；如页面提供停用/启用按钮，再验证状态变化后不可设为主联系人的限制。
5. 以关键词、主营品类、等级、状态、跟进节奏分别筛选；验证总规模、评分、创建时间排序和分页跳转。
6. 基地名称为空、联系人必填项为空时分别提交，确认显示校验提示且不会新增数据。

#### 厂商资料与采购维护

1. 厂商名称为空时保存，确认必填校验；随后新增 C 组厂商。
2. 编辑 C 组厂商的优先级和备注；确认厂商资料表单不出现最近采购时间、最近采购计划，保存后详情、列表和刷新结果一致，跟进人不受编辑请求影响。
3. 联系人执行新增、编辑、设为主联系人、停用和启用；确认主联系人与状态限制正确。
4. 新增采购计划时选择采购品类，并在详情确认品类数量；两个计划包含相同品类时确认厂商汇总不重复计数。
5. 新增两个采购计划：一条用于编辑名称、日期、网页、备注和计划品类；另一条用于删除。确认编辑后采购概况、最近采购计划和时间更新；删除后仅目标计划消失。
6. 以关键词、优先级、电话状态、品类状态分别筛选，确认结果与测试数据一致。

#### 流转校验与列表行为

1. 单条和批量流转分别验证未选择对象时的提示、未填写目标跟进人时的提示、未填写退回或转交备注时的提示。
2. 对已归属当前跟进人的对象执行“分配给同一人”，确认服务端拒绝无效流转且不新增记录。
3. 待分配对象不显示“转交”；已分配对象显示“转交、退回”；详情与列表保持一致。
4. 每次点击基地或厂商“详情”时，用浏览器请求记录确认仅发起一次对应详情请求，且基地对象不会请求厂商详情、厂商对象不会请求基地详情。

#### 审计与错误回查

1. 使用测试名称在操作日志中回查创建、编辑、沟通、流转和删除测试基地等管理员操作。
2. 如任一步骤产生页面错误，立即在错误日志中按时间和请求路径回查；无错误时记录“未发现本轮测试产生的错误日志”。

## 本轮边界

本计划覆盖本次改动涉及的 CRM 功能面：基地主体、基地、厂商、联系人、采购品类、采购计划、通用跟进、跟进任务、流转、权限入口与审计回查。

首页统计图表、地址区域维护、数据字典、角色与权限配置本身不属于本次 CRM 功能验收；仅验证它们为本计划提供的权限和数据源是否可用。
