# 中药材品类统一字典设计方案

> **历史说明：** 品类字典规则仍有效；文中厂商采购计划相关的实体类型已由 `CRM_VENDOR_PURCHASE_PLAN` 更新为 `CRM_PURCHASE_DEMAND`，以 [采购需求标准化设计方案](2026-09-01-采购需求标准化设计方案.md) 为准。

**日期：** 2026-08-31  
**状态：** 已实施，历史设计

## 1. 目标

统一药材基地的主营品类与厂商采购计划的采购品类，使用系统数据字典作为唯一维护来源，消除自由录入带来的同义词、名称不一致和统计口径分裂问题。

## 2. 设计原则

- 复用 `SystemDataDictionaries`，不新增品类业务表。
- 字典子项的 `Code` 与 `Name` 均使用相同的中文品类名称，例如 `黄芪 / 黄芪`。
- 基地与采购计划继续使用 `CrmBusinessEntityAttributes` 保存多选品类，属性值直接保存品类中文名称。
- 基地仍代表种植品类，采购计划仍代表采购品类；两者只统一品类主数据，不合并业务属性。
- 所有新增、编辑和接口写入必须由后端校验字典合法性。

## 3. 字典模型

在系统数据字典中创建一个根节点“中药材品类”。该节点下的启用子项是全系统可选品类。

| 字段 | 规则 |
| --- | --- |
| 根节点 | 名称为“中药材品类”，仅用于组织子项 |
| 子项 Code | 中文品类名称，与 Name 相同 |
| 子项 Name | 中文品类名称 |
| 子项状态 | 启用时可选；停用时不可新增选择 |
| 排序 | 复用字典排序字段 |
| 删除 | 不允许删除已维护品类，只允许停用 |

字典维护入口沿用现有“数据字典”菜单和权限，不新增品类菜单与权限码。已存在的品类子项不允许修改 `Code` 或 `Name`，避免历史属性引用失效。

## 4. 业务数据与校验

### 4.1 基地主营品类

- 实体类型：`CRM_HERB_BASE`。
- 属性编码：`CRM_MAIN_PRODUCT`。
- 属性值必须是“中药材品类”下的启用子项名称。

### 4.2 厂商采购品类

- 实体类型：`CRM_VENDOR_PURCHASE_PLAN`。
- 属性编码：`PURCHASE_PRODUCT`。
- 属性值必须是“中药材品类”下的启用子项名称。
- 前端取消自由输入，只能搜索并多选字典项。

### 4.3 服务端校验

保存基地主营品类与采购计划采购品类时，应用层统一校验提交值：

1. 去空白、去重。
2. 查询“中药材品类”下的启用子项。
3. 所有提交值必须完全匹配子项名称。
4. 不匹配时拒绝保存，并返回明确的非法品类提示。

其他扩展属性不受该校验影响。

## 5. 查询与展示

- 基地新增、编辑、筛选、详情、列表和首页品类分布均使用同一套启用品类字典数据。
- 厂商采购计划新增、编辑、详情、关键词检索、品类数及首页采购品类分布均使用同一套启用品类字典数据。
- 字典项停用后，历史属性继续在列表、详情和统计中显示；停用项不再出现在新增、编辑和筛选选项中。

## 6. 历史数据迁移

迁移按以下顺序执行：

1. 创建“中药材品类”根节点。
2. 从未删除的 `CRM_MAIN_PRODUCT` 与 `PURCHASE_PRODUCT` 属性记录中读取品类值。
3. 去除空白、按中文名称去重，为每个有效值补齐字典子项。
4. 不改写已有有效属性值，保证历史基地、采购计划、列表、搜索和统计继续可用。
5. 对纯空白属性值进行清理，不删除有效业务记录。

## 7. 错误处理

- 已停用品类：保存时返回“品类已停用，请重新选择”。
- 不存在品类：保存时返回“品类未在中药材品类字典中维护”。
- 字典查询失败：前端保留当前表单内容并提示加载失败，不提交空值覆盖已有数据。

## 8. 验收标准

1. 数据字典可维护“中药材品类”及其启用、停用和排序。
2. 基地和采购计划均仅能选择该字典中的启用品类，且支持搜索、多选。
3. 厂商采购计划无法自由录入新品类。
4. 直接调用接口提交不存在或停用的品类会被拒绝。
5. 停用品类仍在历史详情、列表与首页统计中展示，但不能再被新建或编辑选择。
6. 历史基地和采购计划品类均能在字典中找到对应项。
7. 基地和厂商的品类筛选、关键词检索、品类数和首页统计使用统一字典口径。
