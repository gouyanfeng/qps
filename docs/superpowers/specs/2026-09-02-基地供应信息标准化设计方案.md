# 基地供应信息标准化设计

**日期：** 2026-09-02  
**状态：** 已实施、已验证

## 目标

将现有基地档案中的主营品类标签，补充为可参与后续供需匹配的结构化供应事实。第一期只管理人工核实的供应快照，不建设库存流水、订单占用、自动匹配、撮合机会或成交扣减。

## 核心关系

```text
基地主体 1..N 具体基地 1..N 供应信息
```

一条供应信息表示一个具体基地在一段有效期内，对一个中药材品类的一组可供条件。同一基地、同一品类可以有多条供应信息，用于区分批次、规格、产新期或价格条件。

供应信息归属具体基地，主体详情只做聚合展示。`HerbBaseSubjectId` 在供应信息中冗余保存，用于按主体筛选、聚合和后续匹配查询；其值始终以具体基地的 `HerbBaseSubjectId` 为准，不允许独立维护。主体负责人是供应信息的唯一跟进归属，不设置供应信息独立负责人或流转记录。

## 数据模型

新增 `CrmHerbBaseSupply`：

| 字段 | 说明与规则 |
| --- | --- |
| `Id` | 主键 |
| `HerbBaseId` | 所属具体基地，必填 |
| `HerbBaseSubjectId` | 所属基地主体冗余字段，可空，与 `HerbBase.HerbBaseSubjectId` 同步 |
| `ProductName` | 中药材品类，必填，来自启用的统一品类字典 |
| `AvailableQuantity` | 可供量；待确认可空，转有效时必须大于零 |
| `QuantityUnit` | 数量单位；待确认可空，转有效时必填，复用采购需求数量单位字典 |
| `Specification` | 规格、等级，如统货、选货 |
| `QualityRequirement` | 质量、检测、认证等条件 |
| `HarvestSeason` | 产新期文本描述；首期不建立独立季节字典 |
| `ExpectedPrice` | 预期价格，可空 |
| `PriceUnit` | 价格单位，可空，如元/公斤 |
| `SupplyCycle` | 供货周期，如现货、7 天内、按产新期 |
| `ConfirmedAt` | 最近核实日期；转有效时必填 |
| `ValidUntil` | 有效截止日；转有效时必填，且不得早于核实日期 |
| `Status` | 待确认、有效、暂停、已售罄、已失效 |
| `Remark` | 补充说明 |

## 状态与候选范围

```text
待确认 -> 有效 <-> 暂停
              |
              +-> 已售罄 -> 有效（重新核实）
              +-> 已失效（终态）
```

- 新建记录默认“待确认”，允许字段不完整。
- 转“有效”时，必须具备品类、正数可供量、数量单位、核实日期和有效截止日。
- 只有状态为“有效”且 `ValidUntil` 不早于当前日期的记录可作为后续匹配候选。
- “暂停”“已售罄”不参与匹配；重新核实后可转回“有效”。
- “已失效”为终态，不可编辑或恢复；出现新供给时新建记录，保留历史。
- 仅“待确认”可删除；其他状态以状态变化保存业务历史。
- 不实施库存扣减、订单占用、自动到期任务或成交同步。

## 历史数据自动生成

迁移时，从既有主营品类属性自动创建供应信息：

1. 以每个未删除的“具体基地 + 去重后的主营品类”为粒度生成一条记录。
2. 仅预填 `HerbBaseId`、`HerbBaseSubjectId`、`ProductName`、`Status = 待确认`；数量、规格、质量、价格、供货周期、核实日期和有效期均为空。
3. 不生成有效供应信息，不影响后续候选匹配结果。
4. 迁移必须幂等：同一基地、同一品类仅自动创建一条待确认记录；已存在人工创建的同品类记录时不重复生成。
5. 原主营品类属性继续作为基地档案标签保留，不由供应信息反向覆盖。

## 页面与接口

- 在药材基地主体详情抽屉新增“供应信息”页签，按具体基地展示供应信息。
- 支持新增、编辑、删除、状态变更；列表展示品类、可供量、规格、供货周期、状态、核实日期、有效期和过期标识。
- 首期不新增独立供应信息工作台；供应信息在基地详情中维护，避免扩大页面和权限范围。
- 新增供应信息列表、新增、编辑、删除、状态变更接口；查询主体详情时聚合返回基地的供应信息。
- 新增权限：`CRM_HERB_BASE_SUPPLY_VIEW` 与 `CRM_HERB_BASE_SUPPLY_MANAGE`。管理员默认授权；管理权限涵盖新增、编辑、删除和状态变更。

## 校验、迁移与验收

- 数据库新增供应信息表、外键及 `(HerbBaseId, Status)`、`(HerbBaseSubjectId, Status)`、`(ProductName, Status, ValidUntil)` 索引。
- 创建和迁移时从具体基地写入 `HerbBaseSubjectId`；基地变更归属主体时，在同一事务同步更新其全部供应信息。服务端校验基地存在且未删除，品类为启用字典项；状态流转和有效化必填项在领域层统一校验。
- 验收覆盖多批次同品类、待确认草稿、有效化拦截、状态候选过滤、自动生成幂等性、权限、后端构建与迁移、前端构建和浏览器全流程。
