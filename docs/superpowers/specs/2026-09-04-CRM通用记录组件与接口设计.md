# CRM 通用记录组件与接口设计

## 目标

统一基地主体和厂商的联系人、沟通记录、流转记录处理，消除重复的前端表单和后端专用入口，同时保留三类记录各自的实体与业务规则。

## 领域边界

不合并 `CrmContact`、`CrmFollowRecord`、`CrmTransferRecord` 三张表。三者分别表示联系人主数据、一次沟通和不可编辑的流转审计。

三类记录只允许关联以下 CRM 对象：

- `HERB_BASE_SUBJECT`：基地主体。
- `VENDOR`：厂商。

单个基地不作为联系人、沟通和流转对象；它们归属于基地主体。

## 前端组件

业务组件放在 `qps-web-admin/src/views/crm/components`，不放入全局 `src/components`：

```text
contact/List.vue
contact/Dialog.vue
follow/List.vue
follow/Dialog.vue
transfer/List.vue
transfer/Dialog.vue
```

`List.vue` 只展示数据和发出操作事件，`Dialog.vue` 只维护表单和提交。保存成功后发出 `saved`；宿主页面负责重新加载详情或列表。

基地详情、厂商详情组合三类列表和弹窗。跟进任务只使用 `follow/Dialog.vue`，保存成功后刷新任务列表。

## 后端接口

接口保留明确的业务对象，不向前端暴露 `entityType`：

```text
/api/admin/crm/herb-base-subjects/{subjectId}/contacts
/api/admin/crm/herb-base-subjects/{subjectId}/follow-records
/api/admin/crm/herb-base-subjects/{subjectId}/transfer-records
/api/admin/crm/herb-base-subjects/{subjectId}/owner

/api/admin/crm/vendors/{vendorId}/contacts
/api/admin/crm/vendors/{vendorId}/follow-records
/api/admin/crm/vendors/{vendorId}/transfer-records
/api/admin/crm/vendors/{vendorId}/owner
```

控制器仅将路由中的主体或厂商 ID 转为内部对象范围；应用层统一联系人、沟通和流转的查询与命令。内部对象范围只允许基地主体和厂商，命令先校验对象存在性，再执行业务操作。

联系人设主、启停后，应用层使用小范围 `switch` 刷新对应的基地主体或厂商摘要；不引入工厂、策略注册表或通用实体仓储。开发阶段删除旧的基地、厂商专用联系人、沟通、流转接口及命令，不保留兼容入口。

## 测试

Playwright 用例保留在 `qps-ui-tests`：

- 基地主体、厂商分别覆盖联系人、沟通、流转的创建和详情回查。
- 跟进任务覆盖公共沟通弹窗提交后刷新。

后端测试覆盖两类实体范围的联系人、沟通、流转命令，以及不存在或不属于当前范围的对象 ID 被拒绝。
