# CRM药材基地主体聚合设计

> **历史设计：** 基地主体聚合已实施，本文保留用于追溯模型决策。

## 背景

当前 `CrmHerbBases` 同时承载“跟进主体”和“具体基地”两种含义，并用 `ParentId` 做自关联。这个结构能临时表达“一家公司下面多个基地”，但列表聚合、无主体基地、跟进记录归属、联系人归属和统计都会变得不清楚。

本次设计目标是把 CRM 的主工作对象固定为“跟进主体”，把具体种植基地作为主体下的明细资产。

## 核心口径

- 有主体时，跟进主体；基地作为主体下的明细。
- 没有主体时，用基地本身生成一个跟进主体，主体类型标记为 `BASE_ONLY`。
- 列表展示主体聚合结果，不直接平铺所有基地明细。
- 联系人、电话、负责人、状态、跟进记录默认挂主体。
- 基地明细保留品类、规模、地址、经纬度、来源和来源证据。

## 推荐数据结构

### CrmSubjects

表示 CRM 跟进对象。

关键字段：

- `Id`
- `SubjectName`：主体名称，可为空。
- `DisplayName`：列表显示名称；有主体用主体名，无主体用基地名。
- `SubjectType`：`COMPANY`、`COOPERATIVE`、`PERSON`、`BASE_ONLY`、`UNKNOWN`。
- `OwnerUserId`
- `Status`
- `Grade`
- `Score`
- `PrimaryContactName`
- `PrimaryContactPhone`
- `Remark`
- `CreatedAt`
- `UpdatedAt`
- `IsDeleted`

### CrmHerbBases

表示具体基地明细。

关键字段：

- `Id`
- `SubjectId`
- `BaseName`
- `Scale`
- `Province`
- `City`
- `Area`
- `Address`
- `Lat`
- `Lng`
- `SourcePlatform`
- `SourceId`
- `Remark`
- `CreatedAt`
- `UpdatedAt`
- `IsDeleted`

供应品类继续使用现有属性表，建议实体类型仍可区分为基地维度；后续如果主体也需要品类汇总，由查询聚合生成。

## 无主体兼容

政府来源只有基地、没有公司或个人时：

- 创建一条 `CrmSubjects`：
  - `SubjectName = ''`
  - `DisplayName = BaseName`
  - `SubjectType = BASE_ONLY`
- 创建一条 `CrmHerbBases`：
  - `SubjectId` 指向上述主体。
  - `BaseName` 使用来源基地名。

这样 UI 和跟进流程都不需要特殊分支：没有主体的基地也能作为一条可跟进对象显示。

## 列表展示

列表查询主体聚合视图：

- 主列显示 `DisplayName`。
- 展示主体类型、联系人电话、负责人、状态、等级、最近跟进、下次跟进。
- 展示聚合字段：基地数、供应品类汇总、总规模、主要地区、来源汇总。
- 可展开查看基地明细。

示例：

```text
维西百心中药材有限责任公司  公司  2个基地  电话 15894599220
  ├─ 维西县保和镇腊八底村木香GAP基地  木香  政府网站
  └─ 维西县永春乡四保村秦艽GAP基地    秦艽  政府网站

某某村黄芪种植基地  无主体基地  1个基地
  └─ 某某村黄芪种植基地  黄芪  政府网站
```

## 跟进流程

- 从列表点“记录沟通”，默认给主体写跟进记录。
- 从某个基地明细点“记录沟通”，仍给主体写跟进记录，但可额外带 `HerbBaseId`。
- 联系人默认挂主体。
- 负责人默认挂主体。
- 子基地不单独维护跟进状态，避免同一主体状态分裂。

## 导入规则

政府来源、百度 POI 或其他渠道导入时：

1. 先生成主体候选键。
2. 有明确主体名时，用规范化后的 `SubjectName` 匹配主体。
3. 无明确主体名时，用 `BaseName + Area + Address` 生成 `BASE_ONLY` 主体。
4. 找到主体则复用，没找到则新增主体。
5. 基地明细按 `SourcePlatform + SourceId` 幂等插入。
6. 同主体多个基地都挂到同一个 `SubjectId`。

## 迁移策略

从现有 `CrmHerbBases` 迁移时：

1. `ParentId IS NULL` 且同主体第一条记录生成主体。
2. 有 `ParentId` 的记录作为基地明细，归属到父记录生成的主体。
3. 原来没有主体但有基地名的记录生成 `BASE_ONLY` 主体。
4. 联系人、负责人、跟进记录迁移到主体。
5. 供应品类、规模、地址、来源信息保留到基地明细。

迁移后，旧 `ParentId` 只作为兼容历史字段，不再作为列表聚合主逻辑。

## 验收标准

- 列表按主体聚合，不再直接把同一主体的多个基地平铺成重复客户。
- 没有主体的基地能正常展示、分配、跟进。
- 同一主体的多个基地能展开查看。
- 主体联系人和跟进记录不会因为多个基地分散。
- 可按主体名称、基地名称、品类、地区、来源搜索。
- 政府来源和百度来源可以汇总到同一个主体下。
