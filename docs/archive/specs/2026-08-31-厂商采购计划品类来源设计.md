# 厂商采购计划品类来源设计

> **已废弃：** 本文已由 [采购需求标准化设计方案](2026-09-01-采购需求标准化设计方案.md) 替代。采购计划已迁移为采购需求，属性实体类型统一为 `CRM_PURCHASE_DEMAND`，不得按本文继续开发。

## 目标

厂商采购品类只由采购计划维护。厂商详情、列表筛选、品类数量和首页品类分布都从未删除采购计划的品类属性聚合，不再维护厂商直属采购品类。

## 数据模型

保留 `CrmVendorPurchasePlans` 作为采购计划主表，不新增采购品类明细表。

采购计划品类使用既有 `CrmBusinessEntityAttributes`：

| 字段 | 值或含义 |
| --- | --- |
| `EntityType` | `CRM_VENDOR_PURCHASE_PLAN` |
| `EntityId` | `CrmVendorPurchasePlans.Id` |
| `AttributeCode` | `PURCHASE_PRODUCT` |
| `AttributeValue` | 品类名称 |
| `SortOrder` | 计划内品类展示顺序 |
| `Remark` | 可选数量或规格说明 |

同一采购计划内相同品类只保留一条未删除记录。现有索引可支持按实体、属性编码和值查询；迁移补充未删除记录唯一约束。

`CrmVendorPurchasePlan.Products` 是旧的自由文本摘要，不再作为业务输入、汇总或筛选来源。数据库字段暂时保留，便于历史记录回查；新建和编辑计划不再读写该字段。无法可靠拆分的历史自由文本不自动转换为品类，避免产生错误主数据。

## 写入流程

1. 前端在新增或编辑采购计划时，从属性选项接口多选品类。
2. 请求以 `ProductNames: string[]` 传递计划品类。
3. 创建或更新采购计划后，应用层通过既有属性维护能力，将该计划的 `PURCHASE_PRODUCT` 属性整体覆盖为请求值。
4. 删除采购计划时，同时软删除该计划的品类属性，避免已删除计划继续影响厂商品类汇总。

## 查询与聚合

厂商品类的有效集合定义为：

```text
CrmVendorPurchasePlans（同厂商、未删除）
  -> CrmBusinessEntityAttributes（EntityType=CRM_VENDOR_PURCHASE_PLAN、EntityId=计划 ID、AttributeCode=PURCHASE_PRODUCT、未删除）
  -> AttributeValue 去重
```

- 厂商详情返回去重后的品类名称列表和数量。
- 厂商列表 `ProductCount`、关键词品类命中和“有/无品类”筛选使用同一集合。
- 首页“厂商采购品类分布”使用同一集合统计。
- 采购计划分页接口返回每条计划的 `ProductNames`，详情页面在计划行内展示品类标签。

## 页面调整

- 删除厂商详情的“采购品类”独立维护区、“新增品类”按钮及相关弹窗。
- 采购计划表单改为“采购品类”多选，来源保持属性选项接口。
- 计划列表的“品类数量”改为显示本计划的品类数量；需要时以标签展示具体名称。
- 厂商概要仍展示品类数，但含义明确为全部采购计划的去重品类数。

## 历史数据

- 删除既有 `EntityType=CRM_VENDOR`、`AttributeCode=PURCHASE_PRODUCT` 的厂商直属属性，不参与任何查询或统计。
- 现有计划的 `Products` 自由文本保留在原字段，不自动解析。
- 需人工补齐的历史计划，可在计划编辑页重新选择规范品类。

## 验收

1. 新增计划并选择多个品类，厂商详情和列表显示去重后的品类数量。
2. 两个计划选择相同品类，厂商品类数量按去重计算。
3. 编辑计划品类后，厂商详情、列表、关键词和有/无品类筛选同步变化。
4. 删除计划后，其品类不再参与厂商聚合。
5. 刷新页面后，计划品类和厂商聚合结果保持一致。
