# 撮合机会推进流程设计方案

**日期：** 2026-09-08  
**状态：** 已实施（2026-09-08）

## 一、目标

将撮合机会从“候选加自由文本下一步”调整为可统一执行、可统计、可回查的人工撮合闭环。

本方案明确区分三类信息：

| 信息 | 作用 | 保存位置 |
| --- | --- | --- |
| 生命周期状态 | 表达机会是否仍可推进 | 撮合机会 |
| 撮合阶段 | 表达当前推进到哪一段业务流程 | 撮合机会 |
| 当前待办 | 表达下一件要做的标准动作及计划时间 | 撮合机会 |
| 过程记录 | 保存已完成动作、判断结果和推进原因 | 通用业务活动记录 |

本期的“撮合成功”表示供需双方确认可合作，且至少选定一条当前有效的供应；不创建订单、不锁定库存、不代表交付完成。

## 二、业务前提

进入撮合入口前，采购需求和供应信息已完成基础准入：

1. 采购需求为“有效”。
2. 供应明细为“有效”且未过有效期。
3. 品类、数量、规格、质量、交期等信息已可用于人工比较。

因此，机会推进中不再设置“确认需求”“确认供给”这类重复动作。后续处理的是本次撮合条件、商务条件和合作意向是否成立。

## 三、标准流程

```text
有效采购明细
    -> 候选筛选
    -> 创建撮合机会
    -> 匹配核实
    -> 商务沟通
    -> 意向确认
    -> 撮合成功 / 未成交 / 需求取消
```

### 1. 候选筛选

候选筛选发生在创建机会前。业务人员从符合基础条件的供应明细中选择一条或多条候选，必要时使用地区、规格、质量、供货周期和价格筛选条件进一步缩小范围。

候选查询只展示有效、未过期的供应。供应信息尚处于“待确认”时，不是候选数据缺失，而是未达到撮合准入条件。

### 2. 创建撮合机会

至少选择一条候选后创建机会。系统快照采购条件、候选供应条件和创建时的跟进人，机会生命周期状态为“推进中”，初始撮合阶段为“匹配核实”。

创建时必须安排第一项当前待办和计划时间。候选筛选本身作为创建活动和加入候选活动留在时间线中，不将其作为机会创建后的当前阶段，避免出现“候选已经选定但机会仍显示候选筛选”的矛盾。

### 3. 匹配核实

核实本次撮合的关键条件是否匹配，包括数量、规格、质量和交期。条件不匹配时可以淘汰候选、追加候选或继续保留候选。

### 4. 商务沟通

在基础条件可匹配后，沟通价格、付款、运输、交付等商业条件。撮合推进不直接修改原始采购需求和供应信息；来源资料发生事实变化时，仍在对应档案中维护。系统保留本轮快照并提示当前条件差异，由业务人员补充候选、调整阶段或关闭机会，不强制关闭后重建。

### 5. 意向确认

供需双方对合作条件达成一致后，将一条或多条候选标记为“中选”。多个中选候选仅表示可共同供给，本期不记录分配数量。

### 6. 关闭

机会只能以“撮合成功”“未成交”或“需求取消”关闭。

| 关闭结果 | 前置条件 | 必填信息 |
| --- | --- | --- |
| 撮合成功 | 处于“意向确认”阶段，至少一条候选为中选，且当前供应仍有效 | 无额外原因 |
| 未成交 | 不存在中选候选 | 关闭原因 |
| 需求取消 | 不存在中选候选 | 关闭原因 |

已关闭机会不可恢复或编辑。若采购需求仍有效，重新撮合必须新建机会，以保留上一轮完整历史。

## 四、状态与阶段

### 1. 生命周期状态

| 状态 | 说明 |
| --- | --- |
| 推进中 | 可以维护候选、推进阶段和当前待办。 |
| 暂停 | 暂时停止处理，保留当前阶段和待办；恢复时若计划时间已过，必须重新安排待办。 |
| 已关闭 | 本轮结束，只读保存结果和历史。 |

生命周期状态不承担业务进度表达，不能用“推进中”代替具体阶段。

### 2. 撮合阶段

| 阶段 | 进入条件 | 主要目标 |
| --- | --- | --- |
| 匹配核实 | 创建机会后默认进入 | 确认数量、规格、质量、交期可匹配。 |
| 商务沟通 | 至少存在一条可继续推进的候选 | 确认价格、付款、运输、交付条件。 |
| 意向确认 | 商务条件已具备合作基础 | 选择最终合作供应并完成合作确认。 |

阶段仅允许相邻跳转：`匹配核实 <-> 商务沟通 <-> 意向确认`。例如商务沟通失败后，可退回“匹配核实”追加新的候选；不得从“匹配核实”直接跳到“意向确认”。阶段变更必须填写本次结果，并记录在时间线。

### 3. 保存字段与历史回填

撮合机会增加“撮合阶段”和“其他待办说明”两个字段；现有“下一步”和“计划时间”字段继续使用，但“下一步”改为标准动作值。

| 字段 | 规则 |
| --- | --- |
| 撮合阶段 | 固定为“匹配核实”“商务沟通”“意向确认”；创建时默认为“匹配核实”。 |
| 下一步 | 固定为本方案列出的标准待办动作。 |
| 其他待办说明 | 仅当下一步为“其他”时必填。 |
| 计划时间 | 与下一步同时必填。 |

迁移时，历史机会的撮合阶段统一回填为“匹配核实”。历史未关闭机会原有的自由文本下一步保留到“其他待办说明”，下一步统一回填为“其他”；已关闭机会保留原有关闭结果和历史活动，不补写新的活动记录。

## 五、当前待办与过程记录

### 1. 当前待办

当前待办只表示“接下来要做什么”，一条机会始终只保留一组当前待办和计划时间。待办动作使用标准下拉项：

| 适用阶段 | 标准动作 |
| --- | --- |
| 匹配核实 | 核实数量、核实规格与质量、核实交期、安排样品或看货 |
| 商务沟通 | 沟通价格、沟通付款与运输、等待对方反馈 |
| 意向确认 | 确认合作意向、确认中选供应 |
| 全阶段 | 补充候选、其他 |

选择“其他”时显示补充说明输入框并保存到“其他待办说明”；其余标准动作不允许被自由文本替换。计划时间始终必填。标准动作、阶段和关闭结果由后端统一定义中文常量，前端仅消费同一组值，不各自维护字符串。

### 2. 推进记录

“推进机会”是唯一的日常推进入口，提交时必须填写：

1. 本次结果或判断。
2. 变更后的撮合阶段。
3. 下一项待办动作。
4. 下一项待办计划时间。
5. 选择“其他”时的补充说明。

提交后，系统在同一事务内更新机会的阶段、当前待办和计划时间，并新增一条不可变的通用业务活动记录。活动内容以中文保存本次阶段、结果和下一项安排，供时间线回查。

“更新下一步”入口由“推进机会”替代，避免只修改计划而没有结果记录。暂停、恢复、候选保留、中选、淘汰、关闭仍保留各自的明确动作和时间线记录。

## 六、候选处理规则

| 操作 | 规则 |
| --- | --- |
| 追加候选 | 仅推进中机会可追加；供应必须当前有效且尚未在本轮出现。 |
| 保留候选 | 保持后续继续比较的资格，也可用于撤销中选或恢复误淘汰候选。 |
| 淘汰候选 | 必须填写淘汰原因，保留历史判断。 |
| 中选候选 | 仅在当前供应有效时允许；中选不等于订单或交付。 |

当前供应失效或条件变化时，历史候选不删除。详情页面提示“已失效”或“条件已变更”，业务人员据此补充候选、调整阶段或关闭机会；中选和成功关闭时再次校验供应当前仍有效。

## 七、页面交互

### 1. 候选筛选页

- 继续作为采购需求菜单的唯一撮合入口。
- 先选择采购明细，再筛选并勾选候选。
- 创建按钮区域展示初始待办下拉框、计划时间和“其他”补充说明。
- 不在厂商详情中增加撮合入口，厂商详情只维护采购事实数据。

### 2. 机会详情

- 标题区域展示生命周期状态、撮合阶段、当前待办和计划时间。
- 将“更新下一步”替换为“推进机会”。
- “推进机会”弹窗使用阶段选择、标准待办下拉、计划时间和本次结果输入，字段顺序按业务推进顺序排列。
- 候选表保留追加、保留、中选、淘汰操作及供应当前状态提示。
- 时间线按时间展示创建、候选判断、推进记录、暂停恢复和关闭结果。

### 3. 机会列表

- 增加“撮合阶段”列。
- 当前“下一步”列展示标准待办、计划时间和是否逾期。
- “操作”列中，推进中和暂停的机会提供“推进”快捷入口。点击后打开与详情页完全相同的推进弹窗，不再要求先进入详情。
- 暂停机会提交推进时，在同一事务内恢复生命周期、更新阶段、保存本次结果、保存新待办和计划时间，并写入一条过程记录；任一步失败则全部回滚。
- 默认排序保持“推进中优先、计划时间升序、空计划时间置后、更新时间倒序”。

### 4. 跟进任务边界

本期不将撮合机会待办接入跟进任务菜单。日常入口限定为撮合机会列表的“推进”和机会详情的“推进机会”，避免在未定义任务生成、完成、归属和逾期规则前扩展任务工作台。

## 八、架构边界

1. 撮合机会继续是以一条采购明细为中心的聚合；候选是该机会内的判断快照。
2. 阶段、当前待办、其他待办说明和计划时间属于机会实体，应由实体方法校验和更新。
3. 候选状态继续由候选实体维护；应用层负责查询当前供应有效性和写入通用业务活动记录。
4. 过程时间线继续复用既有通用业务活动表，不新建仅用于撮合日志的表。
5. 不将撮合机会接入主体、厂商的沟通记录；后者仍用于客户档案沟通，撮合推进记录只属于具体机会。
6. 不建设订单、合同、库存锁定、候选承担数量或自动撮合评分；这些能力出现明确业务需求后再独立设计。

## 九、验收标准

1. 创建机会时仅能选择有效、未过期供应，并能选择初始标准待办和计划时间。
2. 创建后默认阶段为“匹配核实”，列表和详情均可见。
3. 每次“推进机会”都必须留下本次结果和新的待办安排，旧待办不丢失，能在时间线回查。
4. 暂停保留阶段；恢复时过期待办必须重新安排。
5. 候选失效或条件变化仍可回查，不能被直接中选或成功关闭。
6. 仅“意向确认”阶段可撮合成功关闭，且至少存在一条当前有效的中选候选；未成交和需求取消必须填写原因。
7. 已关闭机会只读；再次撮合创建新机会，旧机会历史不变。
8. 历史未关闭机会的自由文本下一步回填为“其他”及其补充说明，历史过程记录不丢失。
