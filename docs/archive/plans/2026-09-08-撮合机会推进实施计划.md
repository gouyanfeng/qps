# 撮合机会推进实施计划

> **供智能执行代理使用：** 必须使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 逐任务执行。所有步骤使用复选框跟踪。

**目标：** 为撮合机会增加阶段化推进、标准待办和不可变过程记录，并在机会列表和详情页提供统一的日常推进入口。

**架构：** 保留“推进中、暂停、已关闭”生命周期，增加“匹配核实、商务沟通、意向确认”阶段。当前待办保留在机会聚合，过程记录复用 `CrmBusinessActivities`；后端输出阶段和待办选项，前端不硬编码同一组业务字符串。暂停机会通过一次推进提交恢复、更新阶段和待办并写入活动。

**技术栈：** .NET 8、EF Core 8、MediatR、SQL Server、Vue 3、TypeScript、Element Plus、xUnit、Playwright。

**设计依据：** [撮合机会推进流程设计方案](../specs/2026-09-08-撮合机会推进流程设计方案.md)

**实施状态：** 已完成。领域规则、接口、共享推进弹窗和列表快捷推进均已落地；2026-09-08 已在 `5174/5001` 完成 Edge 页面验收，并通过 `crm-05-match-opportunity.spec.mjs` 回归。

## 全局约束

- 阶段固定为“匹配核实、商务沟通、意向确认”，只允许保持或相邻跳转。
- 当前待办使用后端统一的中文标准动作；选择“其他”时必须填写其他待办说明。
- 创建和推进必须同时保存待办及计划时间；推进还必须填写本次结果。
- 成功关闭必须处于“意向确认”阶段，且至少存在一条当前有效的中选候选。
- 过程时间线继续使用 `CrmBusinessActivities`，不新建撮合专用日志表；本期不接入跟进任务。
- 后端临时测试项目放 `E:\Code\QPS\agent-temp`；浏览器测试、截图和报告放 `E:\Code\QPS\ui-tests`。
- 浏览器验收固定使用 `5174/5001`，不得占用或停止 `5173/5000`。

- [x] **步骤 3：实现领域规则**

`CanTransit` 只允许当前阶段、前一阶段和后一阶段；`Create` 默认“匹配核实”。机会新增 `Stage`、`NextActionRemark`，并实现：

```csharp
public void Advance(string stage, string nextAction, string nextActionRemark, DateTime? nextActionAt)
{
    EnsureCanUpdate();
    if (!CrmMatchOpportunityStage.IsValid(stage) || !CrmMatchOpportunityStage.CanTransit(Stage, stage))
        throw new InvalidOperationException("撮合阶段仅允许保持当前阶段或相邻跳转");
    CrmMatchOpportunityNextAction.Validate(nextAction, nextActionRemark);
    EnsureNextAction(nextAction, nextActionAt);
    Stage = stage;
    NextAction = Trim(nextAction);
    NextActionRemark = Trim(nextActionRemark);
    NextActionAt = nextActionAt;
}
```
