# CRM 业务闭环路线图

**更新时间：** 2026-09-01  
**当前阶段：** 采购需求标准化设计

## 目标

将当前以基地、厂商线索管理为主的 CRM，逐步建设为可管理供给、需求、撮合和成交结果的中药材供需撮合平台。

目标业务链路：

```text
供给方建档 -> 供应信息维护
                         -> 供需匹配 -> 撮合推进 -> 成交与复购
需求方建档 -> 采购需求维护
```

## 已完成

- [x] 基地主体、基地明细、厂商档案
- [x] 联系人、主联系人、沟通记录
- [x] 负责人流转与流转记录
- [x] 跟进任务工作台
- [x] 厂商采购计划
- [x] 品类统一字典
- [x] 基地历史组合、模糊和规格品类清洗

## 待持续治理

- [ ] 泛化品类“中药材、其他中药材”等原始来源回查与补全

该事项不阻塞核心业务功能建设。对无法从原始来源确认的记录，保留泛化品类，不作猜测性覆盖。

## 第一阶段：采购需求标准化

### 已确认规则

- [x] 采购需求使用“采购需求单 + 采购需求明细”模型。
- [x] 一张需求单可包含多个采购品类；每条明细独立维护数量、规格、价格和交期。
- [x] 采购需求的来源采购计划为可选关联。
- [x] 支持业务人员直接新建人工录入需求。

### 待完成

- [ ] 定义采购需求状态及状态流转规则。
- [ ] 定义采购需求单字段：需求方、来源采购计划、联系人、负责人、总体备注。
- [ ] 定义采购需求明细字段：品类、数量、单位、规格、质量要求、目标价格、交期、收货地。
- [ ] 定义权限与负责人规则。
- [ ] 设计领域模型、数据库结构、接口和迁移方案。
- [ ] 在厂商详情页增加采购需求入口和列表。
- [ ] 增加采购需求工作台，支持筛选、跟进和关闭。
- [ ] 提供从采购计划转为采购需求的操作入口。
- [ ] 补齐测试、验收记录和发布验证。

### 阶段产出

业务人员能创建、维护和跟进结构化采购需求；每条需求可明确回答“谁需要什么、需要多少、何时需要、要求是什么”。

## 第二阶段：基地供应信息

- [ ] 建立供应信息模型：品类、可供量、规格、质量条件、产新期、价格预期、供货周期。
- [ ] 在基地或基地主体详情页维护供应信息。
- [ ] 支持供应信息有效期和状态管理。

### 阶段产出

业务人员能维护可用于匹配的标准化供给信息。

## 第三阶段：供需匹配与撮合

- [ ] 按品类、地区、数量、交期和质量条件筛选候选基地。
- [ ] 建立撮合机会，关联一条采购需求与多个供应候选。
- [ ] 记录报价、样品、验收、谈判和下一步动作。
- [ ] 记录成交、流失、失败原因和复购机会。
- [ ] 建设匹配漏斗、转化率和品类供需看板。

### 阶段产出

平台可从采购需求出发完成候选供给方筛选、撮合推进和结果复盘。

## 当前优先级

下一项工作为“采购需求标准化”。在完成需求和供应两侧的结构化信息前，不建设自动匹配、推荐或成交管理功能。
