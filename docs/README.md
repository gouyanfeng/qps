# QPS 文档目录说明

本目录存放长期有效的项目文档，全部随代码入库。仓库根 `AGENTS.md` 是唯一的文档索引入口，本文件只说明各子目录的边界，不列文档清单、不标状态。

## 目录边界

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `product/` | 业务背景、角色、业务链路、项目范围 | 表结构、接口字段、实现细节 |
| `operations/` | 环境要求、端口、构建/启动/迁移/发布命令、产物目录、常见故障 | 架构理由、业务规则 |
| `architecture/` | 项目依赖、模块启用、分层、Pipeline 顺序、权限模型、共享层边界 | 具体业务字段、页面样式 |
| `domain/` | 实体清单、状态机、金额/库存/售后口径、唯一约束 | 接口路径、前端组件 |
| `contracts/` | URL、方法、请求/响应字段、错误码、鉴权要求 | Handler 内部实现、数据库表 |
| `design/` | 页面结构、交互、视觉基准、组件选型 | 后端实现、未评审的脑暴 |
| `decisions/` | 为什么这样选、放弃了什么、影响范围（ADR） | 操作步骤、代码片段全集 |
| `archive/` | 已完成或已失效的计划、规格、验收、审计、变更记录 | 任何仍指导开发的内容 |

## 命名规则

- 目录名、文件名一律小写英文 kebab-case（`[a-z0-9-]`），中文只保留在文档第一行 H1 与索引链接文字里。
- 长期事实文档用 `<topic>.md`，不带日期、版本、状态后缀。
- 接口契约用 `<module>-<scope>-api.md`；页面规格用 `<page>-spec.md`。
- ADR 用 `adr-0001-<slug>.md`，编号 4 位、只增不减。
- 归档文件保留 `YYYY-MM-DD-` 前缀，正文不改。
- 禁止出现大写字母、下划线、空格，以及「最终 / 新版 / 最新 / v2 / -old / 副本」等后缀。

## 写作约定

- 每份长期文档第 1 行为 `# 标题`，第 3 行为元信息块：`> 状态：有效 | 最后核对：YYYY-MM-DD | 对应代码：路径`。
- 同一事实只维护一处，其他地方写「见 [文档名](相对路径)」，不复述表格或命令。
- 正文最多 3 级标题，一级小节用 `## 1.` 编号。
- 引用其他文档一律使用相对路径 Markdown 链接。

## 相关工具

阅读器生成脚本为 `tools/build-docs-viewer.mjs`，在仓库根执行 `node tools/build-docs-viewer.mjs` 会重新生成 `docs/docs-viewer.html`。脚本自动遍历本目录，跳过 `archive/`、HTML 文件与以下划线开头的文件，无需维护清单。
