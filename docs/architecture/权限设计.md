# 权限设计方案

本文档用于让后续开发者或 AI 快速理解 QPS 项目的权限设计。当前方案追求简单、直观、少封装。

## 核心原则

权限码是唯一判断依据。

后端 `SystemPermissions.Code` 是权限来源，前端不再维护按钮权限映射表，也不再使用 `BUTTONS.xxx` 这类别名。

页面上需要控制权限的地方，直接写真实权限码：

```vue
<Permission code="CRM_HERB_BASE_CONTACT_PRIMARY">
  <el-button>设为主</el-button>
</Permission>
```

这样读页面时可以直接看到按钮受哪个权限控制。

## 权限分类

权限分两类，但都存放在 `SystemPermissions` 中。

页面权限控制菜单和页面入口：

```text
HOME
CRM_HERB_BASE
CRM_VENDOR
SYSTEM_USER
SYSTEM_PERMISSION
```

按钮权限控制页面内具体操作：

```text
CRM_HERB_BASE_ADD
CRM_HERB_BASE_EDIT
CRM_HERB_BASE_DELETE
CRM_HERB_BASE_ASSIGN
CRM_FOLLOW
CRM_HERB_BASE_STATUS
CRM_HERB_BASE_CONTACT_ADD
CRM_HERB_BASE_CONTACT_EDIT
CRM_HERB_BASE_CONTACT_PRIMARY
CRM_VENDOR_ADD
CRM_VENDOR_EDIT
CRM_VENDOR_DELETE
CRM_VENDOR_ASSIGN
```

## 命名规则

按钮权限使用：

```text
页面权限码_操作
```

例如：

```text
CRM_HERB_BASE
CRM_HERB_BASE_ADD
CRM_HERB_BASE_EDIT
CRM_HERB_BASE_CONTACT_PRIMARY
```

不要在前端把 `contactPrimary` 转换成 `CONTACT_PRIMARY`。权限码应显式写出来。

## 前端实现

前端使用 `Permission` 组件控制插槽显示：

```text
admin/src/components/Permission/index.vue
```

组件职责只有一个：判断当前用户权限列表是否包含传入的 `code`。

页面用法：

```vue
<Permission code="SYSTEM_USER_ADD">
  <el-button type="primary">新增用户</el-button>
</Permission>
```

如果还需要业务条件，业务条件写在插槽内部：

```vue
<Permission code="CRM_HERB_BASE_CONTACT_PRIMARY">
  <el-button v-if="!row.isPrimary" type="primary" link>设为主</el-button>
</Permission>
```

不要恢复或新增 `useAuthButtons` 这类映射封装。

## 后端职责

后端负责维护权限数据和登录后的权限返回。

主要职责：

```text
1. 在初始化逻辑中维护标准权限。
2. 维护权限父子关系。
3. 按角色分配权限。
4. 清理废弃权限。
5. 登录后返回当前用户拥有的权限码列表。
```

废弃权限只应放在退休权限清理名单里，不应再次创建。

例如废弃的联系人无效功能权限：

```text
CRM_HERB_BASE_CONTACT_INVALID
```

它只能用于历史数据清理，不能出现在标准权限和前端页面中。

## 角色策略

`admin` 角色拥有完整权限。

初始化逻辑只保证普通 `user` 角色拥有以下入口：

```text
HOME
```

因此普通用户默认不能进入基地或厂商管理。需要业务人员维护卖方和买方时，应由管理员为其授予 `CRM_HERB_BASE`、`CRM_VENDOR` 及对应操作权限。

厂商页面的新增、编辑、联系人、跟进记录和采购需求维护使用 `CRM_VENDOR_ADD`、`CRM_VENDOR_EDIT`、`CRM_VENDOR_ASSIGN`、`CRM_PURCHASE_DEMAND_VIEW`、`CRM_PURCHASE_DEMAND_MANAGE` 等权限控制；基地供应信息使用 `CRM_HERB_BASE_SUPPLY_VIEW`、`CRM_HERB_BASE_SUPPLY_MANAGE`。新增细粒度权限时，后端初始化、角色授权和前端 `Permission` 用法必须同步更新。

## 新增权限流程

新增一个按钮权限时按以下流程：

1. 后端新增标准权限码。
2. 给需要的角色授权。
3. 前端用 `Permission` 组件包裹按钮。
4. 构建验证前端。

示例：

```vue
<Permission code="CRM_HERB_BASE_EXPORT">
  <el-button>导出</el-button>
</Permission>
```

不要新增前端权限映射，不要使用隐式拼接规则。
