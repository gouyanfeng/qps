# 模块化单体架构

本文档说明 QPS 后端当前的模块化单体结构，用于替换早期按技术分层划分的 4 项目方案。

改造范围仅限代码组织与项目结构：API 路由、统一响应格式、权限码、数据库表/列/索引及迁移历史均保持不变，前端无需调整。

## 项目结构

```text
src/
  QPS.Shared/         公共契约、异常、分页、Pipeline 行为与领域事件
  QPS.System/         系统模块：认证、用户、角色、权限、字典与日志
  QPS.Crm/            CRM 模块：基地、厂商、采购需求、撮合机会、跟进任务与首页图表
  QPS.Persistence/    单一 AppDbContext、实体配置、迁移、当前用户与 JWT
  QPS.Host/           组合根：启动、鉴权、Swagger、过滤器与中间件
tests/
  QPS.UnitTests/
  QPS.ArchitectureTests/
```

各模块内部统一为 `Domain`、`Contracts`、`Application`、`Controllers` 四层；`QPS.Persistence` 负责 `Database`、`Configurations`、`Identity`、`Migrations`。

## 依赖方向

```text
QPS.Shared
   ↑
QPS.System
   ↑
QPS.Crm
   ↑
QPS.Persistence
   ↑
QPS.Host
```

约束：

- `QPS.Shared` 不引用任何业务模块、持久化或 Host。
- `QPS.System` 不引用 `QPS.Crm`、`QPS.Persistence`、`QPS.Host`。
- `QPS.Crm` 不引用 `QPS.Persistence`、`QPS.Host`。
- `QPS.Persistence` 不引用 `QPS.Host`。
- 禁止任何形式的循环项目引用。

## 模块注册即启用

`QPS.Host/Program.cs` 的注册顺序：

```csharp
builder.Services.AddQpsShared();
builder.Services.AddQpsPersistence(builder.Configuration);
builder.Services.AddQpsSystem(builder.Configuration, mvcBuilder);
builder.Services.AddQpsCrm(builder.Configuration, mvcBuilder);
```

每个模块的 `AddQpsXxx()` 只做两件事：

1. `AddMediatR(cfg => cfg.RegisterServicesFromAssembly(模块程序集))`，只扫描本模块的 Handler。
2. 向 MVC 的 `ApplicationPartManager` 加入本模块程序集，只暴露本模块的 Controller。

Host 启动时先清空默认的 `ApplicationParts`，再只添加 Host 自身，因此未调用 `AddQpsXxx()` 的模块既没有 Handler 也没有 Controller 参与运行。模块启用完全由组合根代码决定，不使用 appsettings 开关，也不做运行时动态 DLL 加载。

`QPS.System` 为必装模块；`QPS.Crm` 是否装配由 `AddQpsCrm()` 是否调用决定。

## 公共 Pipeline

三个 Pipeline 行为集中在 `QPS.Shared/Pipeline`，由 `AddQpsShared()` 统一注册：

| 行为 | 职责 |
| --- | --- |
| `PermissionBehaviour` | 读取 Request 上的 `PermissionAttribute`，通过 `IPermissionChecker` 校验功能权限 |
| `ValidationBehaviour` | 执行 FluentValidation 校验器，失败时返回业务异常 |
| `TransactionBehaviour` | 通过 `IUnitOfWork` 包裹写操作事务 |

领域事件由 `IDomainEventDispatcher` 分发，适配 MediatR 的 `IPublisher`。

业务模块不得再定义自己的 Pipeline 行为，避免同一请求被重复拦截。

## 单一 DbContext

`QPS.Persistence/Database/AppDbContext` 是唯一的 DbContext，同时实现 `ISystemDbContext`、`ICrmDbContext`、`IUnitOfWork`。`AddQpsPersistence()` 只注册一次 `AppDbContext`，三个接口通过作用域别名指向同一实例。

实体配置按模块拆分：

```text
QPS.Persistence/Configurations/
  System/SystemModelConfiguration.cs
  Crm/CrmModelConfiguration.cs
```

拆分只调整代码组织，未修改表名、列名、索引与关系。

## 模块边界与跨模块访问

`QPS.System` 是必装模块，CRM 不再为其维护服务抽象：

- CRM 可以直接通过 `ICrmDbContext` 查询 `SystemUsers`、`SystemDataDictionaries`。
- CRM 禁止访问 System 内部实现：`QPS.System.Application` 命名空间、`ISystemDbContext`、`SystemRoles`、`SystemPermissions`、`SystemRolePermissions`。
- `IPermissionChecker` 是保留的跨模块契约：公共 Pipeline 位于 `Shared`，而 `Shared` 不能引用 `System`，因此由 System 实现、Shared 消费。

## 环境与数据库

- Development：启动时执行 `Database.MigrateAsync()` 应用迁移。
- 非 Development：仅执行 `Database.CanConnectAsync()` 校验连接，不自动迁移。

## 架构测试

`tests/QPS.ArchitectureTests` 把上述约束固化为测试，共 14 项，分布在四个文件：

| 文件 | 校验内容 |
| --- | --- |
| `ProjectReferenceTests` | 项目引用方向、循环依赖 |
| `ModuleBoundaryTests` | `Shared` 不引用业务模块；`Crm` 不访问 System 内部实现 |
| `ModuleRegistrationTests` | 未注册模块不产生 Handler/Controller；注册后可解析 |
| `PipelineTests` | 公共行为只存在于 `Shared`，业务模块不重复实现 |

## 新增模块

1. 新建类库 `QPS.Xxx`，引用 `QPS.Shared`，按需引用 `QPS.System`。
2. 提供 `DependencyInjection.AddQpsXxx()`：注册本模块 MediatR 程序集、`ApplicationPart` 与自身服务。
3. 如需持久化，在 `QPS.Persistence/Configurations/Xxx` 增加实体配置，并参照 `IMallDbContext` 新增对应模块的 DbContext 接口。
4. 在 `QPS.Host/Program.cs` 调用 `AddQpsXxx()` 即完成启用。
5. 同步更新架构测试中的项目清单与边界规则。

## 实体命名

实体统一使用「模块前缀 + 实体名」：

| 模块 | 前缀 | 示例 |
| --- | --- | --- |
| `QPS.System` | `System` | `SystemUser`、`SystemRole`、`SystemOperationLog` |
| `QPS.Crm` | `Crm` | `CrmVendor`、`CrmHerbBase`、`CrmMatchOpportunity` |
| `QPS.Mall` | `Mall` | `MallStore`，后续如 `MallProduct`、`MallOrder` |

实体类名、表名与 `DbSet` 属性名保持同名复数形式（如 `MallStore` → `MallStores`），使模块归属在代码和数据库中都可直接识别。
