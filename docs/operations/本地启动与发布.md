# 本地启动与发布

本文档是 QPS 当前仓库的运行指引。研发历史计划中的旧路径和命令以本文为准。

## 目录与端口

- 后端：`qps-ht/`，调试端口 `5000`。
- 管理端：`qps-web-admin/`，开发端口 `5173`。
- 本地 IIS 后端：`20004`，管理端默认通过 `.env` 访问 `http://localhost:20004/api`。
- 本地 IIS 管理端：`20005`，物理路径为 `qps-web-admin/dist/`。
- 测试和临时产物：`qps-ui-tests/`，不提交仓库。

## 开发启动

独立启动后端调试服务：

```powershell
dotnet run --project .\qps-ht\src\4.QPS.WebAPI\QPS.WebAPI.csproj -- --urls http://localhost:5000
```

启动管理端：

```powershell
Set-Location .\qps-web-admin
npm run dev
```

管理端默认连接 IIS 的 `20004`。需要联调后端调试服务时，在本机创建 `qps-web-admin/.env.local`，写入以下内容后重启前端：

```text
VITE_API_URL=http://localhost:5000/api
```

`.env.local` 仅用于本机，不提交仓库。

## 构建验证

```powershell
dotnet restore .\qps-ht\QPS.sln
dotnet build .\qps-ht\QPS.sln --no-restore

Set-Location .\qps-web-admin
npm ci
npm run build
```

前端构建完成后，IIS 的 `CRN_WEB` 站点直接读取 `qps-web-admin/dist/`。

## 发布到本地 IIS

后端发布目录为 `qps-ht/src/4.QPS.WebAPI/bin/Release/net8.0/publish/`。发布前先完成构建验证。

```powershell
dotnet publish .\qps-ht\src\4.QPS.WebAPI\QPS.WebAPI.csproj -c Release
```

若 IIS 锁定 DLL，在发布目录创建 `app_offline.htm`，等待 IIS 卸载应用后再发布；发布完成后删除该文件。最后验证接口：

```powershell
Invoke-WebRequest -Uri "http://localhost:20004/api/admin/crm/herb-bases?page=1&pageSize=1" -UseBasicParsing -TimeoutSec 20
```
