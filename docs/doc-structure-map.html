1. 目录树：唯一入口与各类文档的位置

根 AGENTS 只做索引；README 只做项目介绍；docs/ 下按类型分层；各端 AGENTS 只写本端约束。
  • AGENTS.md唯一文档索引：路径 + 一句话说明 + 必读/选读，不写任何条文索引
    • docs/长期文档根目录，固定 8 个子目录事实
      • product/放：项目背景、角色、业务链路；不放：字段、接口、实现事实
      • operations/放：环境、端口、构建/迁移/发布、排障；不放：架构理由、业务规则事实
      • architecture/放：六项目依赖、分层、Pipeline、权限模型、编码/共享层约定；不放：实体字段、页面样式事实
      • domain/放：实体与表归属、状态机、金额口径、软删除/唯一索引、订单快照；不放：接口路径、组件事实
      • contracts/放：URL、方法、请求/响应、错误码、鉴权；命名 <module>-<scope>-api.md契约
      • design/放：页面结构、交互、视觉基准；命名 <page>-spec.md设计
      • decisions/放：ADR（背景/决策/放弃的方案/影响）；命名 adr-0001-<slug>.md，编号只增不减决策
      • archive/放：已完成计划、规格、验收、审计（只读，不指导开发；当前为 docs/superpowers）归档
    • admin/AGENTS.md管理端：组件复用、共享层禁改、UI 测试纪律约束
    • mobile/AGENTS.md移动端：技术栈、图标/布局/组件规范、常见坑、验收约束
    • web-api/AGENTS.md后端：业务约束、权限码、参数校验、代码风格；命令改为链接 docs/operations约束
    • tools/comfyui/AGENTS.md图片生成脚本用法、参数、输出路径约束
    • tools/build-docs-viewer.mjs阅读器生成工具（入库）：自动遍历 docs/，不维护文件清单；重建命令 node tools/build-docs-viewer.mjs工具
    • agent-temp/会话临时产物：不入库、不进索引、不承诺有效，用完即弃不入库
  • README.md项目介绍 / 技术栈 / 三端最简启动 / 目录概览 / 许可证，不承担索引不索引

文档只有两处：进 docs/ 并入库，或进 agent-temp/ 临时用（不入库）。没有第三处，.trae/ 取消。

索引硬规则：根 AGENTS 只列 docs/ 与各端 AGENTS.md；不得出现 agent-temp/、.trae/ 或未被 git 跟踪的路径。索引不是备份，只是路牌——路径必须可被 git ls-files 命中，否则就是死链。

命名规则：路径全 ASCII，中文只在标题与链接文字

规则
  • 目录名、文件名一律小写 kebab-case，只允许 [a-z0-9-]
  • 文档第一行 H1 用中文标题；索引链接文字用中文（[本地启动与发布](operations/getting-started.md)）
  • ADR：adr-0001-<slug>.md，编号只增不减
  • 契约：<module>-<scope>-api.md；设计：<page>-spec.md
  • 归档保留英文 slug，不保留中文路径；迁移用 git mv
首批重命名
  • 本地启动与发布.md → getting-started.md
  • 实体说明.md → entities.md
  • 模块化单体架构.md → modular-monolith.md
  • 权限设计.md → permissions.md
  • 商城促销规则.md → mall-rules.md
  • 项目背景与业务链路.md → business-context.md

根 README.md 与根 AGENTS.md 的分工

README.md 给人看
  • 项目是什么、技术栈
  • 三端各一行最简启动命令
  • 目录概览、许可证

不写：规范条文、迁移细节、架构理由

AGENTS.md 给会话看
  • 只有索引：相对路径 + 一句话说明
  • 标签：必读 / 选读
  • 让会话知道先读哪几份

不写：命令、条文、表格以外的内容

唯一刻意重叠：三端启动命令在 README 各留最简一行；完整版（迁移、生产发布、排障、端口冲突）只在 docs/operations。
归属口诀：这条内容删掉，谁更会做错事？
只有人会懵（不知道项目是什么、怎么跑）→ README 或 docs
AI 照着干会出错（漏 -m:1、手写事务、漏软删除、读实时表）→ docs 对应章节 + 索引标「必读」
推论：索引不是内容备份，只是路牌。只在 AGENTS 存在、docs 没有的规则视为未落地，迁移时必须先补 docs，不能跟着删。

2. 引用关系：谁指向谁

根 AGENTS 向下只发“链接”；各端 AGENTS 向上只引用对应章节，不转述内容。

根 AGENTS 对 8 个目录只发 8 条索引行，每条 3 列；任何命令与规范正文都不进入根 AGENTS。

各端 AGENTS 保留本端约束，事实一律回到 docs；首屏重复 2–3 条最易踩的硬约束作为兜底。

左侧为现状，中间箭头表示内容去向，右侧为目标索引形态。

① 文件头由新标题承担；② 拆成“协作约定”与“产物目录”；③ 落 admin；④ 落 architecture；⑤ 落 architecture。另五条硬约束（-m:1 / 事务 / 唯一索引 / 快照 / [Permission]）不在根 AGENTS 正文，只在索引里标 必读。
